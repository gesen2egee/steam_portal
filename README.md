# Steam 玩家心得庫

這裡同時提供日常使用的 GitHub Pages 版，以及可完整離線開啟的 `steam_portal.html` 單檔版。兩者由同一次建置產生，會使用相同的版本編號與遊戲資料。

## 版本選擇

- GitHub Pages：日常使用的主要入口。首次只下載搜尋、篩選與卡片所需的目錄資料；開啟遊戲後才下載該組詳情。
- `steam_portal.html`：完整離線備份。心得、核心要點、截圖網址與程式都已包含在單一檔案內，可直接以瀏覽器開啟。

Pages 載入時會顯示已下載與總目錄容量。遊戲詳情如果暫時讀取失敗，只會影響該款遊戲，可按「重試載入」，搜尋與其他遊戲不受影響。

## 主要功能

- 以遊戲名稱、App ID、標籤、類型、開發商與發行商搜尋。
- 依價格、折扣、評價、年份、語言與試玩版篩選。
- 使用探索河道、收藏／願望／已購買與自訂清單；也可保存搜尋、標籤、作者及類似遊戲河道。
- 探索河道保留未讀／已讀的 A／B 交錯順序；設定可選標籤加權、聚類或隨機，預設使用推薦清單出現過的聚類。
- 每款遊戲可建立「類似遊戲」搜尋河道，依 Meta 的 `cluster_id` 取出同聚類作品。
- 以 JSON 匯出或匯入 Portal 狀態備份。
- 在設定中使用 Rentry 跨裝置同步；資料會以 GZIP+Base64 分片保存，更新後可從同一入口網址讀取，並可回復舊版本。
- 從中央 `data/price.json` 顯示價格；「更新價格資料」只會重新讀取這份中央快照。

入口網址使用單一河道路由：`?river=explore`、`?river=list:<清單ID>`、`?river=search:<搜尋ID>`，開啟遊戲時再加上 `&game=<AppID>`。搜尋輸入與篩選會先形成尚未保存的搜尋河道，實際滑過或開啟結果後才保存；搜尋河道會保留上次套用的篩選，清單不保存搜尋篩選。探索河道每次開啟重新建立，但可預取下一次探索內容；預取資料不會出現在清單、JSON 備份或同步資料中。

中央價格超過 12 小時或讀取失敗時，Portal 會保留最後一次有效快取並清楚標示過期，不會直接向 Steam 批次請求價格。

## 匯入 Steam 清單

### 已擁有遊戲

1. 在已登入 Steam 的瀏覽器開啟個人遊戲清單。
2. 將頁面拉到底，確認全部遊戲已載入。
3. 把完整頁面另存為 MHTML。
4. 在 Portal「設定 → 清單管理 → 已購買」匯入該 MHTML。可貼上檔案內容、拖放檔案，或按「選擇 MHTML」。

Portal 會取出已擁有遊戲，並在可辨識時一併取得 SteamID64。

### 願望清單

1. 在設定中輸入 SteamID64。
2. 按「產生網址」並開啟願望清單 JSON。
3. 複製頁面回傳的完整 JSON。
4. 在 Portal「設定 → 清單管理 → 願望」貼上 JSON、拖放 JSON 檔案，或按「選擇 JSON」後預覽；確認無誤再套用。

願望清單與已擁有遊戲匯入會以最後一次完整結果取代對應官方清單；一般自訂清單的文字匯入只會新增項目。
一般文字清單也支援貼上、拖放 TXT 或選擇 TXT，流程都是「預覽」後才「確認新增」。

## 資料保存與備份

收藏、願望、已購買、自訂清單、搜尋河道、閱讀紀錄與設定保存在目前瀏覽器。建議定期使用「同步與備份」內的 JSON 匯出；更換瀏覽器、清除網站資料或使用不同網址時，再匯入備份。

跨裝置同步會把保存的搜尋河道與篩選條件、清單、閱讀紀錄及入口設定壓縮後保存；探索河道本身與下一次預取快取不保存，開啟同步資料後會依目前目錄重新建立。第一次用跨裝置入口網址開啟後，Rentry 網址會記在該瀏覽器，之後每次開啟網頁會自動同步一次。若目前版本驗證失敗，會依序嘗試較早的歷史版本；全部版本都失敗時保留本機資料，不套用同步。每次更新會留下舊版本，設定中的「可回復版本」可將主索引與本機資料一起回復。

## 建置與更新

在專案根目錄執行：

```powershell
python build_portal.py
```

一次會完整更新：

- `html/steam_portal.html`
- `steam_portal/steam_portal.html`
- `steam_portal/index.html`
- `steam_portal/assets/` 與 `steam_portal/data/` 的版本化資源

可用參數：

- `--output-root`：Meta 資料來源。
- `--output`：單檔版輸出位置。
- `--release-dir`：Pages 與單檔副本的發布目錄。
- `--limit`：只讀取前 N 份 Meta，供快速測試。

Builder 會先在暫存區產生並驗證全部輸出，確認兩版的 `build_id` 與遊戲數一致後才啟用新版本。Pages 目錄資料上限為 25 MiB。

## 安全與隱私

- Portal 不需要 Steam 密碼，也不會要求輸入帳號密碼。
- 手動匯入只在目前瀏覽器處理選取或貼上的資料。
- Rentry 同步資料是公開貼文；為了讓跨裝置只需一個網址，主索引會包含 Rentry 編輯碼，因此取得入口網址的人可以讀取、修改或刪除資料。請勿公開分享同步網址。
- 同步資料不包含 Steam 密碼、Token 或 SteamID；但清單內容、收藏與閱讀紀錄仍可能屬於個人資料。
- 發布前請確認 `data/price.json`、備份檔與其他輸出不含私人資料或憑證。
